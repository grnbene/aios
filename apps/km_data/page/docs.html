KM Data API

Read-only access to KM Canada East's ERP data: customers, sales orders, invoices, receivables, salespeople, inventory, vendors and purchasing. Built for loading into a data warehouse; the data is a live copy of the ERP, normally a few seconds behind it.

Getting started

Every request is a GET to with your key in the Authorization header:


    
An answer is one page of rows, in the entity's key order:


{
  "entity": "customers",
  "count": 1000,
  "next": "WyIwMTIzNCJd",
  "rows": [ { "customer_id": "00012", "customer_name": "...", ... }, ... ]
}

    
Keys are issued by QBC. Keep yours out of URLs, logs and source control. A key can be switched off at any
    time; ask for a new one if it stops working.

  


  

    
Paging

    
    
      
  • limit: rows per page, 1 to  (default ).
    • 
      
  • next in each answer is the cursor for the following page: send it back as
        after. When next is null you have every row.
    • 
      
  • Rows always come in key order (the key shown on each entity), so pages never repeat or skip rows,
        even while new rows are being added. Treat the cursor as opaque.
    • 
    


GET v1/invoices?limit=5000
GET v1/invoices?limit=5000&after=WzM0NTY3OF0
...until "next" is null

  


  

    
Filters and CSV

    
    
      
  • from / to (YYYY-MM-DD, both inclusive) on entities with a date. Each entity
        says which of its fields they filter on.
    • 
      
  • Equality filters, listed on each entity: for example customer_id=00012,
        sku=KMU15287, order_id=1100003.
    • 
      
  • format=csv answers the page as CSV with a header row. The cursor for the next page is in the
        X-Next response header (absent on the last page) and the row count in X-Count.
    • 
      
  • A parameter the entity does not have is refused with 400, so a typo never quietly returns everything.
    • 
    

  


  

    
Values

    
TypeFormat

    
Missing values, and dates the ERP holds as blank, are null. All amounts are
    CAD unless a field says otherwise.

  


  

    
Errors

    
An error answers {"error": "<code>", "message": "..."}:

    

      
StatuserrorWhen

      
        
400bad_parameterAn unknown parameter, a bad date, a limit out of range, or a cursor from another entity.

        
401unauthorizedNo key, or a key that is not active on this API.

        
404not_foundNo such entity.

        
500server_errorThe request failed on our side; it is logged. Retry later.

A daily load

    
    
      
  1. First load: page through every entity in full and store the rows keyed on each entity's key.
    2. 
      
  2. Every day after:
        
      
          
    • Reload the small entities in full: customers, customer_locations, salespeople, vendors, items,
            item_prices, inventory_levels, purchase_orders, purchase_order_lines, receipts and lookups.
      • 
          
    • For the large dated ones (sales_orders, invoices, credit_notes, payments, customer_transactions,
            invoice_lines, allocations, inventory_movements, vendor_transactions), load a recent window with
            from (for example the last 7 days) and insert-or-update on the key.
      • 
          
    • sales_order_lines has no date of its own: load the lines of the orders you just loaded
            (order_id=), or reload it in full weekly.
      • 
          
    • Reload receivables in full: it is the current open items, and older invoices drop out of
            it as they are paid.
      • 
        
    
      
    3. 
      
  3. An invoice's amount_applied and open_amount change as it is paid after its
        date. receivables and the customers' balance are always current.
    4. 
    

    
Please run one request at a time per key. Pages of 5,000 rows usually answer in
    under two seconds.

GETv1/sales_by_salesperson

    
Sales per rep per day, on the same basis as the ERP's sales reports (its sales lines, stocktrans):
    invoice and credit note lines as printed, credited to the rep on the document, after line discounts, before tax
    and freight. from and to are required, at most 366 days apart;
    salesperson_id and format=csv are optional.

gross_profitmoneynet_sales - cost.
